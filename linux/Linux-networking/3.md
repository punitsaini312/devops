# 🔹 Step 1: Understand /29

```
/29 means 29 network bits
32 - 29 = 3 host bits
```

Binary:

```
11111111.11111111.11111111.11111000
```

Decimal:

```
255.255.255.248
```

---

# 🔹 Step 2: Block Size

```
Block size = 256 - 248 = 8
```

So subnets increase by **8 in the 4th octet**.

---

# 🔹 Step 3: IP Calculation

```
Host bits = 3
2^3 = 8 total IPs per subnet
Usable = 8 - 2 = 6
```

Each /29 subnet contains:

- 1 Network address
- 6 Usable IPs
- 1 Broadcast address

Total = 8 IPs

Each borrowed bit doubles subnet count:


# Question

I have the network:

```
192.168.0.0/22
```

A `/22` network has **1024 IP addresses**.

Now I subnet it into **/24** networks.

I understand that a `/24` means the first **24 bits are network bits** and the last **8 bits are host bits**.

My confusion is:

> **Why do the subnet network addresses change in the third octet (192.168.0.x → 192.168.1.x → 192.168.2.x)?**
> 
> 
> If the first 24 bits are fixed, shouldn't only the last octet (host bits) change?
> 

---

# Answer

The confusion comes from mixing the **original network** with the **new subnet mask**.

## Step 1: Original network

```
Network: 192.168.0.0/22
Subnet Mask: 255.255.252.0
```

Binary mask:

```
11111111.11111111.11111100.00000000
```

This means:

- First 22 bits = Network
- Last 10 bits = Host

The host bits are:

- Last **2 bits of the third octet**
- All **8 bits of the fourth octet**

So before subnetting, the address range is:

```
192.168.0.0
to
192.168.3.255
```

---

## Step 2: Create /24 subnets

The new subnet mask is:

```
255.255.255.0
```

Binary:

```
11111111.11111111.11111111.00000000
```

Notice what changed:

```
/22
11111111.11111111.11111100.00000000

/24
11111111.11111111.11111111.00000000
```

The **last 2 host bits of the third octet** have now become **network bits**.

These are the bits used to create different subnets.

---

## Step 3: Number of subnets

Borrowed bits:

```
24 − 22 = 2
```

Number of subnets:

```
2² = 4
```

Each subnet contains:

```
2^(32−24) = 256 IP addresses
```

---

## Step 4: The four subnets

| Subnet | Network Address | IP Range |
| --- | --- | --- |
| 1 | 192.168.0.0/24 | 192.168.0.0 – 192.168.0.255 |
| 2 | 192.168.1.0/24 | 192.168.1.0 – 192.168.1.255 |
| 3 | 192.168.2.0/24 | 192.168.2.0 – 192.168.2.255 |
| 4 | 192.168.3.0/24 | 192.168.3.0 – 192.168.3.255 |

---

## Why doesn't the fourth octet create new subnets?

The fourth octet is still the **host portion** of a `/24` network.

For example:

```
192.168.0.0/24
```

The fourth octet can be:

```
0
1
2
...
255
```

These are **hosts within the same subnet**, not different subnets.

Changing:

```
192.168.0.0
192.168.0.1
192.168.0.2
```

does **not** create new subnets.

---

## Key Concept

When subnetting from `/22` to `/24`:

- You borrow **2 host bits**.
- Those borrowed bits are located in the **third octet**.
- Therefore, the **third octet changes** to identify each subnet.
- The **fourth octet remains the host portion** inside each `/24` subnet.

This is why the subnet network addresses are:

```
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

The third octet identifies **which subnet** you are in, while the fourth octet identifies **which host** you are addressing within that subnet.
